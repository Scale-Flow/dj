# dj

A command-line Spotify controller. Check what's playing, skip tracks, search the catalog, look up albums. All output is structured JSON, built for piping into `jq` or feeding to AI agents.

Requires Spotify Premium for playback controls (play, pause, next, previous).

## Install

```bash
go install github.com/scale-flow/dj/cmd/dj@latest
```

Or build from source:

```bash
git clone https://github.com/Scale-Flow/dj.git
cd dj
make build
# binary lands in bin/dj
```

## Setup

1. Create a Spotify app at https://developer.spotify.com/dashboard
2. Run `dj auth login` and enter your Client ID and Secret when prompted
3. Authorize in the browser

The CLI stores tokens in your OS keychain when available, falling back to `~/.config/dj/oauth-tokens.json` on headless systems.

## Usage

```bash
# What's playing right now?
dj player now-playing

# Full playback state (device, shuffle, repeat)
dj player status

# Control playback
dj player play
dj player pause
dj player next
dj player previous

# List connected devices
dj player devices

# Search
dj search --q "Justice D.A.N.C.E." --type track

# Look up a track or album by ID
dj tracks get --id 33yAEqzKXexYM3WlOYtTfQ
dj albums get --id 2WT1pbYjLJciAR26yMebkH
dj albums tracks --id 2WT1pbYjLJciAR26yMebkH
```

## Output Format

Every command writes a JSON envelope to stdout:

```json
{"ok": true, "data": {"is_playing": true, "item": {"name": "D.A.N.C.E."}}}
```

Errors follow the same shape:

```json
{"ok": false, "error": {"code": "unauthorized", "message": "token expired"}}
```

Human-readable messages go to stderr. Pipe stdout freely.

## Headless login (PKCE, no relay or client secret)

Use a Spotify app you control. Add exactly `http://127.0.0.1:8085/callback`
under its allowed redirect URIs. Spotify supports Authorization Code with PKCE;
this is not a device-code flow and still needs one browser authorization.

On the headless machine, run:

```bash
dj auth login start --client-id YOUR_SPOTIFY_CLIENT_ID
```

Open the returned `data.authorization_url` in your own browser. Approve the
requested playback permissions. No listener or relay is started by this flow,
so the browser may show a connection error when it reaches the loopback redirect.
Copy that final callback address, then run in your private terminal on the same
headless machine:

```bash
dj auth login complete
```

Paste the full callback URL at the hidden input prompt and press Enter. Do not
put it in command arguments, shell history, logs, chat, or an issue: it contains
an authorization code. Automated callers may supply it via a private stdin pipe
or restricted file instead. This flow does not bypass browser, network, or
organization access restrictions; if a redirect is blocked by policy, stop and
use an approved environment. Do not copy a blocked callback into another tool.

`start` returns immediately. The private session expires after ten minutes;
`complete` waits no longer than that expiry and allows up to 30 seconds for token
exchange. It validates the exact redirect and OAuth state, uses S256 PKCE, and
consumes the session before exchanging the code. Failed exchanges require a new
login because the code may already have been redeemed. Invalid callback input
can be retried while the original session is valid.

Use the same `--profile NAME` for both commands. `DJ_CLIENT_ID` can replace
`--client-id`. Existing client secrets are not loaded or transmitted by this
flow. Pending verifiers are stored in a private `0700` directory under DJ's
configuration directory with `0600` file permissions; only the public challenge
appears in the authorization URL. Successful tokens use the existing keychain /
private file storage. `dj auth login cancel` discards the pending session (it
does not revoke an already authorized account or interrupt an exchange in progress).
Cancel an expired session before starting again. Do not share pending session files.

The original `dj auth login` relay flow and `dj auth login --local` now stop after
two minutes by default; set `--timeout 5m` to change that (maximum ten minutes).
All login commands support `--dry-run` without authorization or saved state.

Official references: [Spotify PKCE](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow)
and [redirect URI requirements](https://developer.spotify.com/documentation/web-api/concepts/redirect_uri).

For a VM without a working OS keychain, use `auth login complete --storage file`
to explicitly save tokens in the private configuration file. Interactive
completion accepts terminal bracketed-paste sequences and keeps validation
failures at the hidden prompt so you can retry without pasting into a shell.
Use `--auth-storage file` on subsequent API commands when a keychain is present
but broken, for example `dj --auth-storage file player devices`. This explicitly
selects file tokens rather than masking unexpected keychain failures. `auto`
remains the default; `keychain` is also available.
